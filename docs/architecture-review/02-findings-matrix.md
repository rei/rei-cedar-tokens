# Findings Matrix

Legend: **Keep** = carry into future state as-is or nearly as-is · **Adopt from spike** ·
**Adopt from mainline** · **Rebuild** = neither repo's current implementation should
carry forward unmodified.

| Area                                           | Spike                                                                                                                         | Mainline                                                                                          | Decision                                                        | Rationale                                                                                                                                                                                                                                                                                      |

| Source token organization                      | Flat per-concern JSON, normalized into one canonical file                                                                     | Hierarchical, hand-authored tree, no normalization pass                                           | **Adopt from spike** (canonical model), but simplify            | A canonical, schema-validated intermediate representation makes semantic-token validation and cross-platform overrides tractable; mainline's direct-authoring model doesn't support that without duplicating logic per platform.                                                               |

| Platform override handling                     | `$extensions.cedar.platformOverrides` on option tokens, with documented governance rules (ADR-0004)                           | Separate `web/` and `mobile/` token trees                                                         | **Adopt from spike**                                            | Override governance is more scalable than duplicating entire token trees per platform, and keeps a single semantic source of truth.                                                                                                                                                            |
| Generated CSS correctness                      | Duplicate custom-property declarations for the same variable in some modules (hex + OKLCH)                                    | No known duplicate-declaration defect                                                             | **Fix before adoption**                                         | This is a bug in the spike's color-space output step, not an architecture decision; must be corrected regardless of which pipeline wins.                                                                                                                                                       |

| Public package/export surface                  | Not productionized                                                                                                            | Stable `package.json` exports, `validateExportMap()` CI guard                                     | **Keep (mainline)**                                             | This is real distribution infrastructure serving real consumers; no architectural benefit to replacing it.                                                                                                                                                                                     |

## Net Recommendation

For **`color` only**, adopt the **spike's semantic/canonical token model** (corrected
to the five-tier taxonomy) as the source-of-truth authoring and canonicalization
layer, built and distributed through **mainline's Style Dictionary orchestration,
module/type generation, and package export contract**. See
`03-future-state-proposal.md` for detail.

Non-color foundations (`radius`, `spacing`, `typography`, `motion`, `size`, `shape`)
are **not** part of this recommendation and keep their current mainline naming and
structure. Whether/how they get a semantic layer is a separate, not-yet-scoped
decision — see `05-open-questions.md` #3.
