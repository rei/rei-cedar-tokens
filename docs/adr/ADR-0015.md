# ADR 0015: AI Catalog Format

## Status

Proposed — pending stakeholder alignment with Content Design and consumer teams (PDX, Search, Landing)

## Governed paths

Claims in this ADR depend on these paths; a commit touching them may invalidate the status below:

- `scripts/agent-config/` (llms.txt generation pipeline)
- `dist/rei-dot-com/json/web.json` (source for token metadata)
- `docs/adr/` (referenced governance docs)
- `.well-known/llms.txt` (published catalog)

## TL;DR

- Cedar publishes an `llms.txt` file following the [llmstxt.org](https://llmstxt.org) specification
- The file provides a curated, LLM-friendly overview of Cedar's design-system knowledge
- It links to canonical sources: ADRs, token metadata contracts, Storybook, and component documentation
- The format is generated from authoritative sources, not hand-authored
- This serves as the primary discovery mechanism for AI agents (Devin, Figma, Copilot, PDX agents, etc.)
- A companion JSON-LD catalog provides structured data for programmatic consumption

## Problem Statement

AI agents increasingly need to understand Cedar's design-system knowledge to assist with:

- Token selection and usage
- Component composition
- Accessibility validation
- Design-system compliance

Today, agents must scrape multiple surfaces (Storybook prose, documentation sites, source code) to reconstruct Cedar's guidance. This is:

- Inefficient (wastes context tokens)
- Unreliable (prose varies across surfaces)
- Fragmented (no single source of truth)
- Unmaintainable (changes require updates in multiple places)

## Goals

- Provide a single, authoritative entry point for AI agents to discover Cedar knowledge
- Generate the catalog from existing authoritative sources (not hand-authored)
- Follow the llmstxt.org specification for interoperability
- Enable cross-team alignment on shared knowledge distribution (Content Design, Cedar, PDX, Search, Landing)
- Support both human and machine consumers
- Keep the file small enough to fit in context windows

## Architecture

### 1. llms.txt structure

Following the llmstxt.org v2 specification:

```
# Cedar Design System

> Cedar is REI's design system: semantic tokens, UI intents, components, and documentation that provide a consistent, accessible, and on-brand experience across REI's digital products.

Cedar's AI catalog is generated from canonical sources: token metadata (docs/adr/ADR-0006.md), UI intents (docs/adr/ADR-0007.md), modular output architecture (docs/adr/0001-modular-output-architecture.md), and Storybook (the executable reference surface). This file provides a curated overview for agents; detailed information lives behind the links.

## Token Contracts

- [Token Description Contract](docs/TOKEN_DESCRIPTION_CONTRACT.md): Normative grammar for token `$description` fields and `$extensions.cedar.*` metadata
- [Modular Output Architecture](docs/adr/0001-modular-output-architecture.md): Stable entrypoints, public contract surfaces, and token responsibility taxonomy
- [UI Intents Manifest](docs/adr/0007-ui-intents-manifest.md): Coordinated multi-slot token sets for common UI patterns

## Component Documentation

- [Cedar Component Docs](https://cedar.rei.com): Consumer-facing component documentation with usage examples, accessibility guidance, and API references
- [Cedar Storybook](https://storybook.cedar.rei.com): Executable reference surface for tokens, components, and design patterns

## Governance

- [Deprecation Policy](docs/DEPRECATION.md): Token and component deprecation process and timeline
- [ADR Index](docs/adr/): Architecture Decision Records governing Cedar's contract-level behavior

## Optional

- [Token Pipeline Architecture](docs/ARCHITECTURE.md): End-to-end pipeline from canonical tokens to platform outputs
- [AI Preparedness](docs/ai-preparedness-thread.md): Cedar's strategy for making design-system knowledge consumable by agents
```

### 2. JSON-LD catalog

A companion JSON-LD file provides structured data for programmatic consumption:

```json
{
  "@context": "https://schema.rei.com/cedar/context.jsonld",
  "@type": "DesignSystem",
  "name": "Cedar",
  "version": "15.0.0",
  "description": "REI's design system: semantic tokens, UI intents, components, and documentation",
  "tokenCatalog": "dist/rei-dot-com/json/web.json",
  "intentCatalog": "metadata/intents.json",
  "documentation": "https://cedar.rei.com",
  "storybook": "https://storybook.cedar.rei.com",
  "contracts": [
    "docs/TOKEN_DESCRIPTION_CONTRACT.md",
    "docs/adr/0001-modular-output-architecture.md",
    "docs/adr/0006-figma-variable-description-contract.md",
    "docs/adr/0007-ui-intents-manifest.md"
  ]
}
```

### 3. Generation pipeline

The llms.txt and JSON-LD files are generated by a script in `scripts/agent-config/` that:

- Reads the current package version from `package.json`
- Reads token metadata from `dist/rei-dot-com/json/web.json`
- Reads intent metadata from `metadata/intents.json`
- Reads ADR index from `docs/adr/`
- Generates llms.txt following the specification
- Generates JSON-LD with the structured catalog
- Outputs to `.well-known/llms.txt` and `.well-known/cedar.jsonld`

The script runs as part of the build process (`pnpm run build`).

### 4. Publishing

- llms.txt is published at the root of the Cedar docs domain: `https://cedar.rei.com/llms.txt`
- JSON-LD is published at `https://cedar.rei.com/.well-known/cedar.jsonld`
- Both are included in the npm package at the root for local agent consumption
- Version is included in the catalog to enable consumers to track changes

## Alignment with Shared Knowledge Layer

This ADR supports the broader organizational goal of a shared knowledge layer:

- Content Design owns content/UX guidance (emits its own llms.txt from Contentstack)
- Cedar owns component/semantic contracts (emits llms.txt from this ADR)
- PDX, Search, Landing, and other teams consume both without duplicating knowledge
- Agents (Devin, Figma, Copilot, etc.) discover guidance via llms.txt at each domain root

The distribution mechanism (llms.txt) is standardized; the content ownership remains domain-specific.

## Evidence from Consumer Teams

**PDX Agent Content Discovery (2026-11-11):**

PDX team (Harmony) reported that agents cannot effectively read and summarize content from cedar.rei.com. When using the `read_url_content` tool:

- Tool returns chunk positions and summaries instead of actual detailed content
- Example: modal documentation returns "[Position: 10] modal / Accessibility / What Cedar provides + Development responsibilities" rather than the actual guidance text
- Agent cannot extract the structured information it needs (API details, accessibility requirements, etc.)

This validates the core problem this ADR solves: web pages are built for humans (navigation, chrome, JavaScript), making it difficult for agents to extract clean, structured content regardless of the tool used. llms.txt provides a reliable, LLM-friendly entry point that eliminates the need for HTML scraping.

See: `docs/tickets/pdx-agent-content-discovery.md`
