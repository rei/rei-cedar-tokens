# ADR 0005: Mobile Token Metadata via `$extensions.cedar.docs`

## Status

Accepted — partially implemented

## Governed paths

Claims in this ADR depend on these paths; a commit touching them may invalidate the status below (see the `docs-drift` skill):

- `tokens/legacy/mobile/text.json`
- `style-dictionary/configs/android.ts`, `style-dictionary/transforms/android/`, `style-dictionary/actions/android/`, `tokens/options.color.android-dark.json`
- `style-dictionary/legacy/configs/{site.global,site.web,site.ios,canonical}.ts`

- `style-dictionary/legacy/configs/ios.ts` (`CedarText.swift`)

## Implementation Status

Read this before interpreting the Decision section — it describes the target state, not all of it landed.

- **Done:** `$extensions.cedar.docs` on leaf tokens in `tokens/legacy/mobile/text.json` (file has since moved from the `tokens/mobile/` path named in the Decision); group-level `docCategory`/`docType`/`docAndroid`/`docIos`/`docDescription` fields removed.
- **Done:** `scripts/inline-docs-refs.ts` and `scripts/site-tokens.ts` removed; `site/*` JSON outputs (`global.json`, `web.json`, `ios.json`) are emitted with `stripMeta` via `style-dictionary/legacy/configs/site.*.ts`.
- **Done:** `CedarText.swift` emitted via `style-dictionary/legacy/configs/ios.ts` (`ios/swift-text` format).
- **Partial:** Android _outputs_ are removed from the mainline build — no Android platform emits files. However the infrastructure was not fully removed: `style-dictionary/configs/android.ts` still exists (no longer imported by `build.ts` — dead code), Android name/color transforms are still registered in `style-dictionary/build.ts` (the action is commented out pending android extensions in the normalization layer), and `tokens/options.color.android-dark.json` remains as a token source.
- **Open question:** Android transforms remain registered, suggesting Android output may be re-enabled rather than permanently removed — the Decision's "remove all legacy Android generation infrastructure" is in tension with the "action disabled until normalization layer generates android extensions" note in `build.ts`. Resolve before treating Android removal as final.

## Context

Legacy mobile token generation in `rei-cedar-tokens` used a docs-metadata pattern that placed platform names and descriptions at the token-group level and then repeated the same metadata inside each child token's `docs` object. Because those `docs` properties reused values through `{...}` references to sibling properties (for example, `"category": "{text.default.display1.docCategory}"`), Style Dictionary v5 eagerly resolved the braces as broken token references. The `inline-docs-refs.ts` workaround was created to inline those references before SD processed the file.

The spike architecture demonstrated a cleaner pattern: metadata lives inside `$extensions.cedar.docs` on each leaf token. SD v5 does not try to resolve values inside `$extensions` as token references, so the inline workaround is no longer needed. This ADR records the decision to adopt the spike pattern for mobile tokens and to remove the legacy Android/iOS generation infrastructure.

## Decision

- Move all mobile text token documentation metadata into `$extensions.cedar.docs` on each leaf token in `tokens/legacy/mobile/text.json` (originally `tokens/mobile/text.json`; moved when legacy token sources were consolidated under `tokens/legacy/`).
- Remove group-level `docCategory`, `docType`, `docAndroid`, `docIos`, and `docDescription` fields from that file.
- Remove the `scripts/inline-docs-refs.ts` workaround.
- Remove all legacy Android generation infrastructure (`android` platform, `site/android`, `dp-transitive` transform, `style-dictionary/configs/android.ts`, `style-dictionary/configs/site.android.ts`).
- Remove the legacy iOS native output (`CdrSize.h` / `.m`, `CdrColor.h` / `.m`) and replace it with spike-based iOS transforms and a `CedarText.swift` output.
- Remove the custom `style-dictionary/formats/site.ts` format and its SD v5 workarounds (`removeKeyFromNested`, `restoreDollarValueInOriginal`).
- Introduce the `attribute/surface-docs` transform to normalize `$extensions.cedar.docs` onto the top-level `docs` property of every token.
- Switch the `site/*` platforms (`site/global`, `site/web`, `site/ios`) to Style Dictionary's built-in `json` format with `stripMeta` so the generated `global.json`, `web.json`, and `ios.json` are clean, nested DTCG token trees.
- Remove the `site-tokens.ts` aggregation script and its `platform-tokens.json` output; the documentation site now consumes the standard platform JSON outputs directly.

## Consequences

- SD v5 no longer sees unresolved `{...}` patterns in `tokens/mobile/text.json`, eliminating the reference-resolution error the inline script worked around.
- Web consumers are unaffected: web/global tokens still use the `docs` object and web outputs are unchanged.
- iOS consumers now receive a spike-compatible `CedarText.swift` file generated with `name/ios-camel` and `value/ios/text` transforms.
- Android _outputs_ are removed from the mainline build, matching the decision to scope mobile generation to iOS only — but see Implementation Status: Android config/transform/source files remain in the repo (dead code) and the transforms are still registered, so re-enabling Android is possible.
- The documentation site consumes the standard platform JSON outputs (`global.json`, `web.json`, `ios.json`) directly and flattens/groups them as needed, reducing coupling between the token build and the docs site structure.
